# TNT /webui 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/webui`（TUI 内）与 `tnt webui`（独立进程）两个入口，把当前会话实时呈现为网页 —— 聊天流、工具审批、发送、停止 —— 界面取自 DSH 视图层，连接层自写。

**Architecture:** 引擎仲裁对齐 AtomCode AgentHandle 模式：把 messageQueue 的消化收进共享引擎服务（`TurnRunnerService`），TUI 与 WebUiService 都只投递、都订 `eventBus`。WebUiService 在进程内起独立 http server 托管 tnt-webui dist（静态）+ 复用 serve 的 /state、/events SSE、/message、/permission、/pause 路由 + token 门卫。前端独立 repo `tnt-webui`，DSH MIT 视图组件移植 + 自写 SSE adapter。

**Tech Stack:** TypeScript / express（CLI 已有）、SSE（协议已有）、React + Vite + CSS Modules（前端）、vitest（两侧）、zustand（前端 store，对齐 DSH store 引擎）。

**Spec:** `.tnt/superpowers/specs/2026-10-30-webui-design.md`（实现者必须先读）

## Global Constraints

- 端口默认 47610，占用 +1 顺延，最多探 100 个；`--port` 可指定。**禁止复用 `attachBindErrorHandler` 的 `process.exit(1)` 路径**（serve.helpers.ts:393-406）—— 绑定失败必须捕获 EADDRINUSE 顺延，TUI 进程绝不退出。
- v1 只绑 127.0.0.1。不做 lan。
- token：每次启动随机生成；URL `#token=` → bootstrap 页设 HttpOnly cookie 后 302 到 `/`；长驻模式 token 落 `~/.tnt/webui-token`（0600）。
- 代码、注释、提交信息不得出现 "Continue" 一词（namingLedger 冻结计数）。
- 新命令 `webui` 需要 `cmd.webui` 双语 i18n key + 两个 slash-commands.mdx 文档行，同一 commit（slashCommandsDoc.test.ts 双向守卫）。
- 事件协议不改：前端消费 `packages/cli/src/protocol/events.ts` 的 AgentEvent 契约原样（content.delta、tool.*、permission.requested、turn.completed/failed/interrupted 等）。
- DSH 代码搬运保留其 MIT 版权声明（THIRD_PARTY_NOTICES.md）。
- 每个任务 commit 一次，conventional 短句，无 AI 署名。

## Review Focus

1. **浏览器消息在 TUI 空闲时无人消化** —— 期望：立即开跑。→ Task 2 的测试钉住（TurnRunnerService 空闲时也能消化队列）。
2. **无 token 请求拿到会话内容** —— 期望：401/空白。→ Task 4 的测试钉住（门卫对 /state /events /message /permission /pause 全拦截）。
3. **端口被占时 TUI 进程死亡** —— 期望：顺延下一端口。→ Task 4 的测试钉住（EADDRINUSE → 47611）。
4. **停止按钮无效或停错轮次** —— 期望：截断当前轮次，双表面同步看到 turn.interrupted。→ Task 3 的测试钉住。
5. **SSE 断线后前端静默卡死** —— 期望：自动重连 + 明确的断线提示。→ Task 7（前端 adapter）的测试钉住。
