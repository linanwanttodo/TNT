TNT is a command line coding agent. It reads a repository, runs tools, edits files and
answers questions without leaving the terminal. The same engine is reused by the editor
integrations, so anything the agent learns to do works in both places.

## Two ways to run it

| | Interactive | Headless |
| --- | --- | --- |
| Command | `tnt` | `tnt -p "..."` |
| Interface | transcript, composer and status line in the terminal | stdout only |
| Typical use | working inside a repository | scripts, CI, editor integrations |

## What the agent can do

- Read, write and edit files in the workspace.
- Search the codebase and run shell commands, each subject to its permission policy.
- Use MCP servers for extra tools, prompts and resources.
- Delegate work to a subagent that runs on the same engine.
- Load markdown skills and plugins written for the Claude Code plugin format.

Every action passes through the permission system. `agent` mode asks before
high risk operations, `plan` mode is read only, `auto` mode allows everything.
See [Modes](/cli/modes).

## Where things live

| Path | Contents |
| --- | --- |
| `~/.tnt/config.yaml` | models, MCP servers, rules |
| `~/.tnt/permissions.yaml` | permission policies |
| `~/.tnt/settings.json` | hooks and other settings |
| `~/.tnt/skills/` | markdown skills |
| `~/.tnt/plugins/` | installed plugins |
| `~/.tnt/sessions/` | saved chat sessions |
| `~/.tnt/logs/tnt.log` | debug log |

A repository can override most of this from its own `.tnt/` directory.
