## 测量用量

状态栏显示已使用的上下文窗口比例。该数字包含系统消息、工具定义和整个对话，
因此在回答第一个问题之前也可能不是零。

## 自动压缩

会话会在溢出上下文窗口之前被压缩。默认上下文策略：

| 设置 | 值 |
| --- | --- |
| 输入达到多少时压缩 | 上下文窗口的 80% |
| 压缩后原样保留 | 输入容量的 16% |
| 为输出预留的空间 | 64 tokens |

压缩会总结较早的对话、原样保留最近的部分，并在会话记录中写入一个边界，让人能
看到摘要从哪里替换了原始消息。压缩后上下文指示器会重置。

`/compact` 会按需执行同样的操作，适合在长任务开始前使用，而不是在任务中途使用。

## Prompt 缓存

第一次之后的每个请求都会复用前一个请求的前缀，让 provider 能以更低价格提供缓存
部分。provider 返回缓存读取量时，状态栏会显示；日志会记录未命中和发生变化的前缀
状态，这通常能解释缓存命中率为什么突然下降：

| 原因 | 影响 |
| --- | --- |
| 系统消息改变 | 整个前缀失效 |
| 工具增加或删除 | 工具块变化，缓存重建 |
| 子智能体使用了不同的前缀 | 它有自己的缓存 |
| 压缩重写了历史 | 边界之后开始新的前缀 |

子智能体继承父会话的 prompt 缓存键，因此委派会复用父前缀，而不是重新付一次
缓存写入的费用。嵌套委派被有意禁止继续扩散，因为每个新前缀都要支付一次完整的
缓存写入。

## 控制回合长度

`--max-steps <n>` 限制单个回合中的模型往返次数。它是无人值守运行的护栏，不是
上下文设置：上下文上限始终由模型决定。
