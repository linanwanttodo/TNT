## 日志

`~/.tnt/logs/tnt.log` 记录启动、配置解析、MCP 连接、工具调用和缓存统计。可以
为单次运行提高日志级别：

```bash
TNT_LOG_LEVEL=debug tnt
```

无头运行可以使用 `--verbose` 达到同样效果。

## 智能体看不到我的模型

运行 `/model` 检查列表。列表中没有某个模型，说明对应的 `models` 条目没有解析
成功，日志会在启动时报告失败的字段。记住：不存在的 `provider` id 是错误，不会
回退。

## Claude settings 里的模型字段会被忽略

TNT 会读取 `~/.claude/settings.json` 里的 hooks、权限和环境变量，但模型定义与
当前模型放在 `~/.tnt/config.yaml`。Claude 文件里的 `model` 或 `models` 键会按设计
丢弃，只在 debug 级别记录；请通过 onboarding 或 `/model` 配置模型。

## 密钥被拒绝

`${{ secrets.NAME }}` 从环境变量和[配置](/zh/cli/configuration)中的 `.env`
文件解析。用 `TNT_LOG_LEVEL=debug` 打印解析结果，查看密钥相关的行：如果显示的是
占位符而不是值，说明启动 TNT 的进程没有设置该变量。

## MCP 服务器无法连接

`/mcp` 显示每个服务器的状态以及失败原因。在别的工具里可用、在这里不可用，通常
是缺少环境变量，或者相对路径解析到了错误的目录。

## 上下文很快就满了

百分比会把系统消息和工具定义算进去，因此较大的规则文件或工具集会在一开始就占用
一部分上下文。`/compact` 会压缩历史，减少规则集则会减少固定部分。见
[上下文和压缩](/zh/cli/context)。

## 缓存读取降为零

系统消息变化、工具列表变化或压缩边界都会开始新的前缀。日志会记录哪个前缀状态
发生了变化，通常足以定位原因。

## 找不到命令

旧安装可能在 PATH 上留下过期的 shim。用当初使用的包管理器重新安装，或者检查
`which tnt` 指向的安装目录，确认它指向当前版本：

```bash
tnt --version
```

## 重置

配置位于 `~/.tnt/`。把这个目录移到别处，就可以把模型、权限、会话和插件恢复为
默认值，同时保留旧数据用于对比。
