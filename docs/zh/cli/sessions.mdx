会话会在运行过程中写入 `~/.tnt/sessions/`，因此中断的会话不会丢失。

## 会话的位置

每个会话有自己的目录：

```text
~/.tnt/sessions/<session-id>/
  session.jsonl      # 会话记录：头部和追加式记录
  meta.json          # 标题、cwd、时间和列表用的摘要
  tool-results/      # 不放进模型上下文的超大工具输出
  cache-breaks/      # 前缀差异报告
  block-overflow/    # 终端无法显示的行
```

`tnt ls` 和会话内选择器读取 `meta.json`，因此列出很长的历史时不需要打开每个
会话记录。会话记录是唯一事实来源；元数据文件可以从它重建。

同一时刻一个会话只有一个写入者。如果另一个 TNT 进程已经打开了同一个会话，
再次打开会得到明确提示，而不是让两个进程互相覆盖。关闭会话或退出 TNT 会
释放它。

## 恢复

```bash
tnt --resume                # 当前目录最新的会话
tnt ls                      # 从最近会话中选择
tnt ls --json               # 给脚本使用的相同数据
```

在会话内，`/sessions` 列出所有已保存会话，`/resume` 打开选择器，`/title` 或
`/rename` 为当前会话命名，方便以后查找。

## 分叉

`/fork` 把当前历史分叉成一个新会话，这是尝试另一种方案又不丢失原对话的
安全方式：

```bash
tnt --fork <sessionId>      # 启动时直接分叉
```

## 在机器之间移动会话

```bash
/export                     # 把会话写入 JSON 文件
/import                     # 读回一个会话
```

导出的文件包含会话记录和工具结果，因此可以把会话附加到 issue 或迁移到另一台
工作站。

## 委派会话

子智能体作为独立会话运行，并链接到父会话。`/subagents` 列出它们，`/back`
返回父会话；委派会话的记录以只读方式打开。见[子智能体](/zh/cli/subagents)。

## 旧版会话文件

早期版本会保存一个 `<session-id>.json` 文件和一个 `sessions.json` 列表。
这些文件仍然可读，也仍会出现在 `tnt ls` 中。旧会话第一次被写入时，TNT 会把它
转换成目录格式，并把原文件保留为 `<session-id>.json.legacy`；
`sessions.json` 不再写入。

<Warning>
会话文件包含完整对话，包括智能体从仓库读取的任何文本。请把
`~/.tnt/sessions/` 视为敏感数据；除非确实需要，不要放入共享备份。
</Warning>
