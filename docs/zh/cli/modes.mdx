模式是最强的权限层。TNT 有六个值；其中五个可以在 TUI 和 ACP 中选择。

| 模式 | 行为 | 典型用途 |
| --- | --- | --- |
| `default`（手动） | 读取和搜索允许；写入和其他高风险调用会询问 | 日常工作 |
| `acceptEdits` | 四个写入工具在工作区内直接允许；Bash 仍会询问 | 修改已知的改动 |
| `plan` | 写入工具禁用，只运行非修改性 shell 命令 | 修改前调研 |
| `auto` | 分类器决定原本需要询问的调用；失败时失败关闭 | 带安全检查的无人值守 |
| `bypassPermissions` | 所有工具都允许 | 完全信任的显式运行 |
| `dontAsk` | 默认策略表，但所有询问改为拒绝 | 无头模式和 serve 运行 |

## 以某个模式启动

```bash
tnt --permission-mode default
tnt --permission-mode acceptEdits
tnt --permission-mode plan
tnt --permission-mode auto
tnt --permission-mode bypassPermissions --dangerously-skip-permissions
```

旧参数仍然可用，并会打印弃用警告：

| 参数 | 映射到 |
| --- | --- |
| `--mode agent` | `default` |
| `--readonly` | `plan` |
| `--auto` | `bypassPermissions` |

没有参数时，`TNT_PERMISSION_MODE` 或 `CLAUDE_CODE_PERMISSION_MODE` 设置启动
模式。`settings.json` 中的 `defaultMode` 是最后的回退。不是六个合法值之一会
在启动时被拒绝。

`bypassPermissions` 始终需要显式的 `--dangerously-skip-permissions` 参数，
除非环境变量或持久化的 `defaultMode` 已经选择了它。

## 会话内切换

`Shift+Tab` 循环：

`手动 → 接受编辑 → 计划 → 自动 → 绕过权限 → 手动`

输入框边框会显示当前模式。`dontAsk` 是无头模式和 serve 的语义，不会进入 TUI
或 Shift+Tab 循环。

## 计划模式

计划模式在工具运行前强制执行，而不只是告诉模型：

- 四个写入工具（`Edit`、`MultiEdit`、`Write`、`ApplyPatch`）被禁用；
- shell 工具只运行被判定为非修改性的命令；
- MCP 和插件工具会询问，无头运行会拒绝它们；
- 模型应产出计划、决策和 todo 列表，而不是直接修改。

计划准备好后，切换到 `acceptEdits` 或 `default`。

## 自动模式

自动模式保留用户自己的规则，并在原本需要询问的调用上叠加分类器。只读和
元数据工具直接运行；`acceptEdits` 会允许的调用也直接运行；其余交给分类器。
连续三次或累计二十次拒绝后，下一次询问会交回给人。分类器失败或无法解析时
绝不算作同意：交互式运行会询问，无头运行会拒绝。

## ACP

ACP 客户端可以通过 `session/set_mode` 使用 `default`、`acceptEdits`、`plan`、
`auto` 和 `bypassPermissions`。不提供 `dontAsk`。每个会话的 worker 保留自己的
模式，因此两个编辑器会话可以同时使用不同模式。见 [ACP](/zh/cli/acp)。

## 与策略的关系

模式会覆盖[权限](/zh/cli/permissions)中描述的策略。`plan` 和
`bypassPermissions` 只根据模式构建策略列表，因此 `--allow`、`--ask` 和
`--exclude` 无法放宽它们；把这两个模式和这些参数一起使用会被拒绝。
