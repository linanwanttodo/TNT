---
title: "子智能体"
description: "把任务委派给运行在同一引擎上的子智能体。"
---

子智能体在自己的会话中运行任务，同时父会话继续工作。它使用与父会话相同的引擎、
模型和权限模式。

<Info>
在委派接口稳定之前，Subagent 工具由 `--beta-subagent-tool` 参数控制。
</Info>

## 内置角色

CLI 自带八个角色。每个角色有自己的系统提示词和限制，并运行在会话当前使用的模型上。
`ListSubagents` 会把同一份清单交给模型。

| 角色              | 做什么                                                                     | 不能做什么                                    |
| ----------------- | -------------------------------------------------------------------------- | --------------------------------------------- |
| `verification`    | 跑构建、测试与 lint，再主动尝试打破改动；给出 PASS/FAIL/PARTIAL 结论        | 改文件                                        |
| `explore`         | 用 `文件:行` 的证据画出问题在代码里的回答路径                               | 改文件、执行命令                              |
| `debug`           | 复现失败、缩小到根因，给出最小修复与验证命令                                | 改文件                                        |
| `security-review` | 审查注入、授权、密钥、危险文件操作与 SSRF                                   | 改文件                                        |
| `shell`           | 执行任务需要的命令，逐条报告退出码与输出                                    | 改文件                                        |
| `ci-investigator` | 读失败的流水线，指出 job、step 与第一条错误，并对应到代码或运行环境          | 改文件；读不到无法访问的 forge                |
| `browser`         | 在用户打开的浏览器里查看页面：布局、可见性、交互                            | 改文件；读 DOM、控制台或网络                  |
| `best-of-n`       | 写两三个候选方案的 diff 草图，并给出排序与理由                              | 改文件、执行命令                              |

所有角色都不持有 `AskQuestion` 与 `Exit`：委派出去的运行没有人在旁边回答问题，
而 `Exit` 会结束正在汇报结论的那个进程。

## 查看和返回

```
/subagents
```

列出从当前会话委派的会话。

```
/back
```

返回父会话。委派会话的记录以只读方式打开：可以查看子会话，但修改发生在拥有该
工作的会话中，因此两个智能体不能同时改写同一条对话。

## 缓存行为

子智能体继承父会话的 prompt 缓存键，因此共享前缀会从缓存读取，而不是重新付费。
嵌套委派被有意限制得较浅：允许子会话继续扩散会成倍增加缓存写入，复用带来的节省
就消失了。如果委派任务需要更多并行度，这通常意味着应该从父会话拆成两个委派任务。
