title: "子智能体"
description: "把任务委派给运行在同一引擎上的子智能体。"
---

子智能体在自己的持久化会话中运行任务，同时父会话继续工作。它使用与父会话相同的
引擎和模型，权限则从父会话收窄。`Subagent` 默认立即返回 `run_id` 与 `session_id`；
只有调用方需要先拿到最终报告时才传 `run_in_background: false`。

## 内置角色

CLI 自带九个角色。每个角色有自己的系统提示词和限制，默认运行在会话当前使用的模型上；`explore` 在配置了 `roles: ["search"]` 的模型时使用该模型。
`ListSubagents` 会把同一份清单交给模型。

| 角色              | 做什么                                                                     | 不能做什么                                    |
| ----------------- | -------------------------------------------------------------------------- | --------------------------------------------- |
| `verification`    | 跑构建、测试与 lint，再主动尝试打破改动；给出 PASS/FAIL/PARTIAL 结论        | 改文件                                        |
| `explore`         | 只用本地工具，以 `文件:行` 的证据画出问题在代码里的回答路径               | 改文件、执行命令                              |
| `debug`           | 复现失败、缩小到根因，给出最小修复与验证命令                                | 改文件                                        |
| `security-review` | 审查注入、授权、密钥、危险文件操作与 SSRF                                   | 改文件                                        |
| `shell`           | 执行任务需要的命令，逐条报告退出码与输出                                    | 改文件                                        |
| `ci-investigator` | 读失败的流水线，指出 job、step 与第一条错误，并对应到代码或运行环境          | 改文件；读不到无法访问的 forge                |
| `browser`         | 在用户打开的浏览器里查看页面：布局、可见性、交互                            | 改文件；读 DOM、控制台或网络                  |
| `best-of-n`       | 写两三个候选方案的 diff 草图，并给出排序与理由                              | 改文件、执行命令                              |
| `research`        | 搜集网页与工作区信息，报告带引用来源的发现                                  | 改文件                                        |

所有角色都不持有 `AskQuestion` 与 `Exit`：委派出去的运行没有人在旁边回答问题，
而 `Exit` 会结束正在汇报结论的那个进程。

## 查看和返回

```
/subagents
```

列出从当前会话委派的会话。

```
/back
```

返回父会话。委派会话可以查看，父代理可用 `Subagent.session_id` 或
`SendMessage` 继续同一个子会话。

## 后台控制

- `TaskOutput` 读取运行状态与最终报告。
- `SendMessage` 向运行中的子代理发送 steer、续聊已完成的子代理，或让需要父代理
  输入的子代理暂停。
- `TaskStop` 只停止指定子代理，不停止父会话；它会保存取消结果，并发出与自然完成
  相同的完成通知。

## Markdown 智能体

在 `.tnt/agents/<name>.md`、`.claude/agents/<name>.md` 或
`~/.tnt/agents/<name>.md` 中定义智能体，按此顺序优先使用第一个同名文件。
YAML frontmatter 可配置 `model`、`tools`、`disallowedTools`、`permissionMode`、
`maxTurns`、`skills`、`background` 与 `isolation`，Markdown 正文是智能体的系统提示词。
`maxTurns` 限制模型/工具轮数，`tools` 是允许列表，`skills` 会预加载到子会话上下文，
`background: true` 让派发默认异步执行。

在智能体上设置 `isolation: worktree`，或给 `Subagent` 传
`isolation: "worktree"`，即可让文件、搜索、shell 和语言服务器工具在临时 detached
git worktree 中运行。主 checkout 的未提交改动不会复制进去。运行结束（包括失败）时会删除
worktree；它适合隔离检查或实验，不是把改动应用到主 checkout 的方式。续聊子会话时会创建
新的隔离 worktree。

## 专家团

默认提供 `dev` 与 `sec`。`market` 是只读的股票/基金研究团队，包含组合管理、宏观、
基本面、技术面、情绪、风险、执行计划与合规角色。它产出带来源的研究结论以及模拟
交易或待审批草稿；不下单、不转移资金、不保存券商凭证，也不承诺收益。

团队运行共享一份持久化任务列表。lead 和成员都能使用 `TaskCreate`、`TaskGet`、
`TaskList`、`TaskUpdate`，达到委派深度上限的成员也保留这些工具。任务可以依赖已有任务；
被阻塞的任务不能领取，每个任务同时只有一个 owner。`TaskCreated`、`TaskCompleted`
与 `TeammateIdle` 钩子把这些生命周期节点暴露给项目自动化。`TeammateIdle` 钩子阻止完成时，
同一个成员会带着反馈继续工作，成员账本只结算一次。

运行 `/team tasks` 可打开交互式任务列表：Up/Down 导航，Enter 查看详情，Left/Right
选择成员，Space 领取，`c` 完成，`r` 刷新，Esc 返回。

## 缓存行为

子智能体继承父会话的 prompt 缓存键，因此共享前缀会从缓存读取，而不是重新付费。
嵌套委派被有意限制得较浅：允许子会话继续扩散会成倍增加缓存写入，复用带来的节省
就消失了。如果委派任务需要更多并行度，这通常意味着应该从父会话拆成两个委派任务。
