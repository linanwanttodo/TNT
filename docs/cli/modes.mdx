title: "Modes"
description: "agent, plan and auto: what each mode allows and how to switch."
---

A mode is the strongest permission layer. There are three.

| Mode | Behaviour | Typical use |
| --- | --- | --- |
| `agent` | normal work, asks before high risk operations | default day-to-day use |
| `plan` | read only, documentation writes only, shell commands restricted to non-mutating ones | investigating and planning |
| `auto` | every tool allowed without asking | unattended runs |

## Starting in a mode

```bash
tnt                              # agent
tnt --readonly "map the auth flow"   # plan
tnt --auto "fix the lint errors"     # auto
tnt --mode plan                      # same as --readonly
```

## Switching during a session

`Shift+Tab` cycles `agent` to `plan` to `auto` and back. The active mode is shown
in the composer, so the current permission level is never ambiguous.

## What plan mode enforces

Plan mode is not a hint to the model, it is enforced before the tool runs:

- Writes outside documentation file types are refused, and the refusal is
  reported back to the model so it can adapt.
- The shell tool only runs commands recognised as non-mutating.
- The agent is expected to produce a plan, decisions and a todo list rather than
  changes.

Switch to `agent` when the plan is ready.

## Relationship to policies

Modes override the policies described in [Permissions](/cli/permissions).
`plan` and `auto` ignore `--allow` and `--exclude` on purpose: a mode that can be
widened by a flag would not be a guarantee.
