title: "Sessions"
description: "Save, resume, fork, export and import conversations."

Sessions are written to `~/.tnt/sessions/` as they run, so an interrupted session
is not lost.

## Where a session lives

Each session has its own directory:

```text
~/.tnt/sessions/<session-id>/
  session.jsonl      # transcript: a header and append-only records
  meta.json          # title, cwd, timestamps and a summary for listings
  tool-results/      # oversized tool output kept out of the model context
  cache-breaks/      # prefix diff reports
  block-overflow/    # lines the terminal could not show
```

`tnt ls` and the in-session picker read `meta.json`, so listing a long history
does not open every transcript. The transcript is the source of truth; the
metadata file can be rebuilt from it.

A session has one writer at a time. If another TNT process already has the same
session open, opening it again reports that instead of letting two processes
overwrite each other. Closing the session or exiting TNT releases it.

## Resume

```bash
tnt --resume                # the newest session for this directory
tnt ls                      # pick from recent sessions
tnt ls --json               # same data for scripts
```

Inside a session, `/sessions` lists everything saved, `/resume` opens the picker,
and `/title` or `/rename` labels the current one so it is easy to find later.

## Fork

`/fork` branches the current history into a new session, which is the safe way to
try an alternative approach without losing the original thread:

```bash
tnt --fork <sessionId>      # fork on startup instead
```

## Move sessions between machines

```bash
/export                     # write the session to a JSON file
/import                     # read one back
```

The exported file contains the transcript and tool results, so a session can be
attached to an issue or moved between workstations.

## Delegated sessions

A subagent runs as its own session that is linked to its parent. `/subagents`
lists them and `/back` returns to the parent; delegated transcripts open read
only. See [Subagents](/cli/subagents).

## Older session files

Earlier releases stored one `<session-id>.json` file plus a `sessions.json`
list. Those files are still readable and still appear in `tnt ls`. The first time
an old session is written, TNT converts it to the directory format and keeps the
original as `<session-id>.json.legacy`; `sessions.json` is no longer written.

<Warning>
Session files contain the full transcript, including any text the agent read from
your repository. Treat `~/.tnt/sessions/` as sensitive and exclude it from shared
backups unless that is intended.
</Warning>
