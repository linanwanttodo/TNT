---
title: "Subagents"
description: "Delegate a task to a child agent that runs on the same engine."
---

A subagent runs a task in its own persisted session while the parent keeps
working. It uses the same engine and models, with a permission set narrowed from
the parent. `Subagent` returns a `run_id` and `session_id` immediately by default;
pass `run_in_background: false` when the caller needs the final report before it
continues.

## Built-in roles

Nine roles ship with the CLI. Each one carries its own system message and its
own restriction, and runs on whatever model the session is using. The `explore`
role uses a model tagged `roles: ["search"]` when one is configured, so a cheap
model can carry the exploration window. `ListSubagents` shows the same list to
the model.

| Role              | What it does                                                                                   | Cannot                                   |
| ----------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `verification`    | Runs the build, tests and linters, then tries to break the change; answers PASS/FAIL/PARTIAL    | Edit files                               |
| `explore`         | Maps how a question is answered by the code, with `file:line` evidence, using local tools only   | Edit files, run commands                 |
| `debug`           | Reproduces a failure, narrows it to a root cause, returns the smallest fix and how to check it  | Edit files                               |
| `security-review` | Reviews a change for injection, authorization, secrets, unsafe file operations and SSRF         | Edit files                               |
| `shell`           | Runs the commands a task needs and reports each with its exit code and output                   | Edit files                               |
| `ci-investigator` | Reads a failing run, names the job, step and first error, and maps it to the code or the runner | Edit files, reach a forge it cannot see  |
| `browser`         | Inspects a page in the open browser: layout, visibility, interaction                            | Edit files; read the DOM, console or network |
| `best-of-n`       | Writes two or three candidate solutions as diff sketches and ranks them                         | Edit files, run commands                 |
| `research`        | Gathers web and workspace information and reports findings with cited sources                   | Edit files                               |

Every role is declared without `AskQuestion` and `Exit`: a delegated run has
nobody watching it to answer a prompt, and `Exit` would end the process the
result is being reported to.

## Watching and returning

```
/subagents
```

lists the sessions delegated from the current one.

```
/back
```

returns to the parent session. The transcript is inspectable, and the parent can
continue the same child with `Subagent.session_id` or `SendMessage`.

## Background controls

- `TaskOutput` reads a run's status and final report.
- `SendMessage` steers a running child, resumes a finished child, or pauses a
  child that needs parent input.
- `TaskStop` stops one child without stopping the parent turn, records a
  cancellation result and emits the same completion notification as a natural finish.

## Markdown agents

Define an agent in `.tnt/agents/<name>.md`, `.claude/agents/<name>.md`, or
`~/.tnt/agents/<name>.md`. The first matching name wins, in that order. YAML
frontmatter configures `model`, `tools`, `disallowedTools`, `permissionMode`,
`maxTurns`, `skills`, `background` and `isolation`; the Markdown body is the
agent's system prompt. `maxTurns` limits model/tool rounds, `tools` is an
allowlist, `skills` are preloaded into the child context, and `background: true`
makes dispatch asynchronous.

Set `isolation: worktree` on the agent, or pass `isolation: "worktree"` to
`Subagent`, to run file, search, shell and language-server tools against a
temporary detached git worktree. The main checkout's uncommitted changes are
not copied. The worktree is removed when the run ends, including on failure;
use it for isolated inspection or experiments, not as a way to apply changes to
the main checkout. Resuming a child starts a fresh isolated worktree.

## Teams

`dev` and `sec` ship by default. `market` adds a read-only research team for
stocks and funds: portfolio management, macro, fundamentals, technicals,
sentiment, risk, execution planning and compliance. It produces sourced research
and paper-trade or approval drafts; it does not place orders, move funds, store
broker credentials or promise returns.

Team runs share a persisted task list. `TaskCreate`, `TaskGet`, `TaskList` and
`TaskUpdate` are available to the lead and members, including a member at the
delegation-depth limit. A task can depend on existing task ids; blocked tasks
cannot be claimed, and a claim has one owner. `TaskCreated`, `TaskCompleted`
and `TeammateIdle` hooks expose those lifecycle points to project automation.
A blocked `TeammateIdle` hook resumes the same member with its feedback and
settles the member ledger only once.

Run `/team tasks` for an interactive task list. Use Up/Down and Enter to inspect
a task, Left/Right to choose a member, Space to claim it, `c` to complete it,
`r` to refresh, and Esc to return.

## Cache behaviour

A subagent inherits the parent prompt cache key, so the shared prefix is served
from cache instead of being paid for again. Nested delegation is deliberately
kept shallow: allowing children to fan out further multiplies cache writes, and
the saving from reuse is lost. If a delegated task needs more parallelism, that
is a sign the work should be split into two delegated tasks from the parent
instead.
