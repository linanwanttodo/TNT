# Token consumption comparison (research cache)

> 2026-11-13 · Research cache, not a user guide. We compared how the reference implementations (pi, Claude Code, Codex, Cursor) manage context, item by item, against TNT; the conclusions live here for the optimization work to cite.

## Context

One real 66-minute agent session, measured:

| Metric | Value |
| --- | --- |
| Requests | 533 |
| Total input | 112,302,767 tokens |
| Cache-hit input | 111,616,768 (99.4%) |
| Average input per request | 210,699 |
| Context growth | 11,664 → 294,191 |

The high cache-hit ratio means money is not the main problem; the token total and the duration are: 533 requests × 210K at ~7s each fills an hour. The same task under the reference implementations uses an order of magnitude fewer requests and a much smaller working set.

## What the four do, what TNT lacks

| Mechanism | pi | Claude Code | codex | cursor | TNT |
| --- | --- | --- | --- | --- | --- |
| Compaction trigger | window−16K (`compaction/compaction.ts:267`) | absolute threshold + tiered buffer, ~180K on a 200K window (`compact/autoCompact.ts:101`) | model-level token limit or 95% of window (`session/context_window.rs:84`) | per-vendor compactors + segmented layout | 0.8×window; on a 1M window = 800K, never fires |
| Old tool-output eviction | none, relies on compaction | **microcompact: old tool results replaced by `[Old tool result content cleared]`, keeps the latest 5** | none, relies on truncation + compaction | none, relies on compaction | **none** |
| Tool output cap | bash tail 2000 lines/50KB, full copy on disk | bash 30K chars, hard result cap 100K | default 10K tokens per output | — | bash 50K chars, Read 100K chars ≈ 25K tokens |
| Deferred tool loading | default toolset is 4 tools | 29 core tools always loaded, rest deferred | tool_search defers schemas | — | all tools always loaded |
| Parallel tool calls | default parallel | supported | `parallel_tool_calls: true` + dedicated executor | all calls in a step in parallel + per-file write barrier | sequential, one at a time |
| Cutting wasted rounds | — | subagents keep their own message stack, main thread gets a summary report | apply_patch edits multiple files at once | per-tool failure circuit breaker injected into the last tool result | an invalid call costs a full resend |
| Server-side state chain | none | none | `previous_response_id` incremental chaining | — | stateless full resend |
| Cache management | cache-warmer with a savings budget | explicit cache_control breakpoints (max 4) + compaction reuses the main prefix | `prompt_cache_key` + trims from the start to preserve the prefix | breakpoint sliding window, maxCacheBlocks=4 | prefix monitoring, 99.4% hit |

## Root causes, ranked

1. **No tool-output eviction (microcompact)** — the biggest share. Most of the context is historical tool output; a single Read can add 25K tokens and nothing ever shrinks it. Our only shrinking tool is compaction, and on a 1M window its threshold is 800K — unreachable.
2. **The compaction threshold scales with the window.** Claude Code uses an absolute threshold with a tiered buffer; codex a model-level limit. A large window does not mean a large working set.
3. **Too much retained after compaction.** We keep 16% (~160K on a 1M window); pi keeps 20K, codex keeps summary + user messages (20K budget).
4. **Inflated round count.** 65 invalid tool calls + 18 execution failures in one session, each costing a full-context resend.
5. Tool output caps too generous (50K/100K chars vs codex 10K tokens, CC 30K chars).

## Optimization order

1. Tool-output eviction: above a threshold (e.g. 40% of window) replace tool results older than the latest N with `[Old tool result content cleared]`; originals stay in session.jsonl.
2. Absolute compaction threshold: `compactAt = min(0.8×window, absolute cap)`; lower `retainRatio` or cap retained tokens absolutely.
3. Lower tool output caps: Read 100K→50K chars, Bash 50K→30K chars, or token-based.
4. Parallel tool calls: execute multiple tool_calls from one turn concurrently; adapt permission prompts.
5. Per-tool failure circuit breaker: after N consecutive failures of one tool, inject diagnostics into the last tool result and degrade.

Expected: 1/3–1/5 of the tokens for the same task, and minutes instead of an hour.

## Fact-check notes

- DeepSeek's official pricing page confirms the current `deepseek-flash` (DeepSeek-V4.1-Flash-1017) has a 1M context, so our `contextLength: 1000000` preset is not wrong; the problem is compaction policy and missing eviction, not the window declaration.
- cursor evidence comes from static analysis of the unpacked kernel (no source map; references are byte offsets), archived separately.
