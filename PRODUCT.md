# Product

## Register

product

## Users

Local developers and operators who run TNT on their own machine and use the terminal or loopback Web UI to inspect workspaces, settings and agent sessions. They work with local files, local model credentials and local command, skill and hook configuration.

## Product Purpose

TNT is a local-only coding agent shell. Success means every visible control reads or writes real local state, and no account, subscription, plan or migration surface appears. Unavailable remote capabilities must not be represented as inert controls.

## Brand Personality

Direct, technical, calm and locally sovereign. The interface should feel like a dependable tool, not a hosted service.

## Anti-references

Do not imitate hosted SaaS account dashboards, login walls, pricing pages, upgrade prompts, migration wizards or placeholder menus that fail silently. Avoid decorative onboarding and cloud-entitlement affordances.

## Design Principles

- Local state is the only product state.
- Every exposed control has a real local operation behind it.
- Remove capabilities that do not belong in TNT instead of hiding them behind flags.
- Input handling follows the terminal and preserves IME and slash-command behavior.
- Errors are concrete and recoverable; unsupported capabilities are absent.

## Accessibility & Inclusion

Target WCAG 2.1 AA for the Web UI. Preserve keyboard and IME input, visible focus, readable contrast and reduced-motion behavior. Settings must remain usable without an account, pointer device or cloud connection.
